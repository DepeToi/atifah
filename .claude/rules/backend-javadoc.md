# 后端注释规范

> 本文件职责：**只补充或修正注释，绝不改变代码行为**。
> 适用范围：`atifah-common`、`atifah-gateway`、`atifah-services`、`atifah-admin-web/backend` 全部后端 Java 代码。

## 1. 职责红线（最重要）

补充或修正注释时，以下行为一律禁止：

- 不改任何代码逻辑、表达式、控制流、返回值；
- 不改方法签名、参数、泛型、访问修饰符、注解；
- 不增删 import、不调整字段顺序、不重命名任何标识符；
- 不改字符串字面量、枚举值、常量、配置；
- 改动范围仅限注释，diff 白名单见「第 2 节」。

若发现代码本身有问题，不顺手修，只按本文件补注释；问题另行提出。

## 2. diff 白名单

补充/修正注释后，用 `git diff` 自检改动范围，**只允许**出现：

- 新增或修改 `//` 行注释、`/* */` 块注释、`/** */` JavaDoc；
- JavaDoc 标签：`@param`、`@return`、`@throws`、`@author`、`@since`、`@see`、`@deprecated`；
- 修正注释中的错别字、错误描述、过时的参数/返回值说明。

除第 1 节列出的代码改动外，以下同样视为越界：

- 调整注释所在行的代码缩进、换行、格式；
- 借补注释之名夹带代码改动（顺手加日志、改默认值、删空行等）；
- 在注释中写入敏感明文示例值（见「第 10 节 字段注释模板」）。

## 3. 优先补充范围

- 公共 API、接口方法、record 参数、构造器。
- BO / VO / Entity 字段，尤其是导入导出、翻译、权限相关字段。
- Mapper 默认方法、Service/Controller 公开方法。
- 公共模块里的私有辅助方法，如果涉及映射、批量处理、状态复制、降级语义。

## 4. 注释风格

- 描述“做什么”和关键参数语义，不复述每行实现。
- `@param` 名称必须和方法签名一致。
- `void` 方法不要写 `@return`。
- 无抛出异常的方法不写 `@throws`。
- 布尔返回值说明 true/false 含义。
- 简单框架覆写方法可不重复注释；如果当前文件已有统一注释风格，保持一致。
- 只修正错注释时，尽量保持最小 diff。

## 5. 常见错注释

- 方法实际查询全部数据，注释写成“根据用户查询”。
- 方法返回树、映射、分页，`@return` 只写笼统“结果”。
- 参数从 ID 集合变成 Collection，注释还写“ID 串”。
- `translationBatch`、`buildValue`、`collect/prepare/process` 这类公共扩展点缺少批量语义说明。

## 6. 注释语言与基本格式

- 一律中文，标点使用全角（，。：；）。
- 类、接口、方法用块注释 `/** ... */`；字段、枚举常量用单行 `/** ... */`。
- 一句话描述末尾加句号「。」；标签（`@param` / `@return` / `@throws`）对齐书写。

## 7. 类注释模板

```java
/**
 * 一句话说明该类的职责与用途。
 *
 * @author <作者>
 * @since <版本，如 1.0.0>
 */
```

- 实体、DTO/VO、配置类、工具类、抽象基类、启动类均适用。
- `@author` / `@since` 必填；`@author` 填作者或团队名，`@since` 填引入版本号。不得删除文件里已存在的版本信息。

## 8. 接口注释模板

```java
/**
 * 一句话说明该接口的契约与职责。
 *
 * @author <作者>
 * @since <版本>
 */
```

## 9. 方法注释模板

```java
/**
 * 一句话说明该方法的行为。
 *
 * @param <name> <参数含义>
 * @return <返回值含义>
 * @throws <异常类> <触发条件>
 */
```

- 关键方法必须写：业务方法、public 对外方法、含复杂逻辑的私有方法。
- getter/setter、纯转发样板方法可只写单行 `/** ... */`，但**不得删除既有注释**。
- record 组件注释写在 record 声明上，用 `@param <组件名>` 逐个说明，形式同方法注释。

## 10. 字段注释模板

```java
/** <字段含义>。 */
```

- 实体字段、配置项、常量、枚举值均适用。
- 敏感字段（日记正文、量表结果、手机号、密码）注释中**不得出现明文示例值**。

## 12. 自检

- 运行 `git diff --check`。
- 检查是否只改注释或文档。
- 检查新增 JavaDoc 是否和当前实现一致。
- 用 `git diff` 核对改动范围是否落在「第 2 节 diff 白名单」内。
