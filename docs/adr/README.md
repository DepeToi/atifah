# 架构决策记录（ADR）

> 记录“为什么这么定”，避免同一问题反复讨论。只写已确认的决策，不写草案。
> 规则入口见根 [`AGENTS.md`](../../AGENTS.md)；设计细节见 [`../architecture.md`](../architecture.md)。

## 何时写

- 影响多个模块或长期维护成本的技术选型；
- 难以回滚的架构调整；
- 与 `AGENTS.md`、`docs/rules/*`、契约相关的重要规则变更；
- 被否决但以后可能重提的方案（写清否决原因）；
- 三工具分工、契约冻结、评审门禁等协作流程变更。

## 命名与状态

- 文件名：`NNNN-短标题.md`，四位递增编号，例如 `0001-auth-login-token.md`。
- 状态：`提议` / `已采纳` / `已废弃` / `已替代`。被替代时保留原文，在新 ADR 中链接。
