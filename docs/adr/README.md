# 架构决策记录（ADR）

> 记录「为什么这么定」，避免同一问题反复讨论。只写已确认的决策，不写草案。
> 规则入口见根 [`AGENTS.md`](../../AGENTS.md)；设计细节见 [`../architecture.md`](../architecture.md)。

## 何时写

- 影响多个模块或长期维护成本的技术选型；
- 难以回滚的架构调整；
- 与根 `AGENTS.md`、`.claude/rules/*` 相关的重要规则变更；
- 被否决但以后可能重提的方案（写清否决原因）。

## 命名与状态

- 文件名：`NNNN-短标题.md`，四位递增编号，例如 `0001-ai-rules-layering.md`。
- 状态：`提议` / `已采纳` / `已废弃` / `已替代`。被替代时保留原文，在新 ADR 中链接。

## 模板

```markdown
# NNNN. 标题

- 状态：已采纳
- 日期：YYYY-MM-DD
- 决策人：<!-- 姓名或角色 -->

## 背景

要解决什么问题？有哪些约束？

## 决策

我们决定做什么？边界是什么？

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A | | | 采纳 / 否决 |

## 影响

- 正面：
- 负面/代价：
- 需要同步修改的文档与代码：
```
