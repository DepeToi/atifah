# 0001. 精简 AI 协作与评审流程

- 状态：已采纳
- 日期：2026-11-07
- 决策人：项目维护者

## 背景

当前 Claude、CodeBuddy、Codex 的角色边界清晰，但任务状态需要同时维护 front matter 与变更日志，Codex 通常重复执行 CI 已覆盖的全量测试，评审报告还需要额外 docs-only 提交归档。对于流程搭建阶段，这些重复记录和验证增加了交接成本。

## 决策

- 保留 Claude 负责架构与契约、CodeBuddy 负责 Feature 实现、Codex 负责只读评审的分工。
- Feature 状态只维护任务包 front matter；Git 提交历史与关联 PR 作为状态变更依据，不再要求单独维护状态日志。
- PR 评论作为 Codex 评审结果和测试证据的默认记录位置；评审报告文件可按需归档，但不作为合并或任务关闭的前置条件。
- Codex 首先核验 Reviewed SHA 对应的 CI 结果。CI 已覆盖的全量构建不要求重复执行；仅在 CI 缺失、失败、覆盖不足或风险较高时补跑相关测试。
- 安全、契约、公共模块、网关、数据库与消息链路等高风险变更仍须进行针对性验证，并记录未覆盖范围。
- 任务验收、契约冻结、范围约束、Blocker/Major 修复要求与人工合并权限保持不变。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 保持现有双重状态日志、全量复测与强制报告归档 | 留存形式统一 | 重复 CI 与记录步骤多，流程门槛高于当前需要 | 否决 |
| 以 PR 为协作记录，按风险复用 CI 并按需归档 | 减少重复步骤，风险门禁仍保留 | 评审记录依赖 PR 平台长期可访问 | 采纳 |

## 影响

- 正面：减少任务状态重复记录、重复全量测试和仅用于报告归档的提交。
- 负面/代价：完整评审记录默认保存在 PR 评论中；如需仓库内长期索引，可按需归档。
- 需要同步修改的文档与代码：`AGENTS.md`、任务包规范与模板、Codex 评审标准、评审报告说明、Git 规则、PR 模板。
- 回滚方式：恢复上述文档中原有的状态日志、全量自测与强制归档要求。
