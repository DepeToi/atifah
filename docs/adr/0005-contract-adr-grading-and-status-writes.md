# 0005. 契约 ADR 分级与任务状态减写

- 状态：已采纳
- 日期：2026-11-12
- 决策人：项目维护者

## 背景

第二轮流程优化（`TODO.md` P2/P3）针对两处过度写法：

- DOC-01 原文要求“契约变更先有 ADR”，未区分变更性质。兼容新增（新增可选字段、新增接口、新增通用错误码）也走 ADR，Arch 阶段产物与实际风险不匹配，拖慢契约迭代。
- 任务状态机按 P0 试点的实际做法，每次状态变化都单独提交，容易产生只改 front matter 的“status-only PR”，评审与 CI 都要跑一遍，收益为零。

## 决策

- **契约 ADR 分级**：ADR 仅对以下情形必需——首次冻结、破坏性变更、跨服务语义变更、新组件引入。兼容新增只需契约 diff + 变更说明，走 `arch/<topic>` 契约 PR，合并后按需打新基线标签，不再要求 ADR。
- **状态减写**：
  - 允许直接以 `ready` 创建任务包（前提：契约已冻结 + 基线标签 + 维护者确认）；`draft` 仅用于例外。
  - `in-review` 与开 PR 放在同一提交，不单独提交状态。
  - `done` 由维护者在 PR 合并后批量收口，不要求每个 PR 后立即提交。
- **禁止 status-only PR**：仅修改任务包 front matter（`status` / `updated` / `status_reason`）的 PR 不予合并；状态变更必须与对应的实现、契约或评审证据在同一 PR 内，或由维护者在合并后批量收口。
- **不做**：不新增状态、不新增角色、不拆分状态机文档；权限模型（谁能设哪个状态）保持不变。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 所有契约变更一律要求 ADR | 产物统一，容易检查 | 兼容新增也写 ADR，成本高于风险 | 否决 |
| 按变更性质分级，兼容新增免 ADR | 产物与风险匹配 | 需要评审判断“是否破坏性” | 采纳 |
| 保留每次状态单独提交 | 流转记录清晰 | 产生 status-only PR 噪音 | 否决 |
| 状态随同 PR/批量提交，并禁止 status-only PR | 提交次数降到 ≤2 次 | 状态流转需靠 PR 与 Git 历史还原 | 采纳 |

## 影响

- 正面：兼容新增契约不必写 ADR；正常任务的 state 提交从 3–4 次降到 ≤2 次；不再出现只改状态字段的 PR。
- 负面/代价：判断“兼容还是破坏性”依赖评审经验，误判会绕过 ADR 门禁；因此破坏性变更仍由 DOC-01 拦截，`in-review → ready` 需写明原因。
- 需要同步修改的文档与代码：`docs/review/standards.md`（DOC-01 分级）、`docs/contracts/README.md` §3/§4、`docs/contracts/api-conventions.md` §10、`AGENTS.md` §0（Arch 必需产物）、`docs/tasks/README.md` §2（状态机与禁止 status-only PR）、`docs/tasks/_TEMPLATE.md`。
- 回滚方式：恢复 DOC-01 原文“契约变更须 ADR”，删除禁止 status-only PR 条款，恢复每次状态单独提交。
