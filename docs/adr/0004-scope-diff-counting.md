# 0004. SCOPE-02 只统计生产语义行

- 状态：已采纳
- 日期：2026-11-11
- 决策人：项目维护者

## 背景

T-001 的 PR #7 共 14 个文件、906 行新增，其中生产代码约 273 行、测试代码约 318 行。原 SCOPE-02 只写“语义 diff ≤400 行”，未说明测试代码是否计入，Codex 评审因此提出 `[Question]`。

若测试也计入，会迫使拆分任务或压缩测试覆盖；若完全不计，又可能让测试规模失控。项目需要一条可执行、不会惩罚测试的口径。

## 决策

- SCOPE-02 的 400 行只统计生产代码、SQL、配置、契约与规则的语义新增/删除行。
- 测试代码、纯格式化、生成文件不计入。
- 测试代码规模仍需在 PR 描述中说明；评审关注覆盖质量与关键路径，不以行数作为硬性上限。
- 本条为统计口径澄清，不改变“一个 PR 只对应一个任务/变更”与“超出请拆分”的原则。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 生产语义行与测试行都计入 | 口径简单 | 迫使拆分测试或减少覆盖，首个纵向切片即超限 | 否决 |
| 生产语义行计入，测试单独设上限 | 控制总量 | 需要额外阈值，当前无数据支撑 | 暂不采纳 |
| 只计生产语义行，测试在 PR 中说明 | 鼓励测试，贴合实际评审 | 测试规模需靠评审把关 | 采纳 |

## 影响

- 正面：任务拆分按生产代码规模判断，测试覆盖不被行数惩罚；T-001 的 273 行生产代码符合上限。
- 负面/代价：超大测试集需要评审关注；后续可积累数据再定测试规模阈值。
- 需要同步修改的文档与代码：`docs/review/standards.md`、`docs/tasks/README.md`、`docs/rules/git-workflow.md`、`AGENTS.md`、`docs/adr/README.md`。
- 回滚方式：恢复“语义 diff ≤400 行”的原文，删除本 ADR 与相关引用。
